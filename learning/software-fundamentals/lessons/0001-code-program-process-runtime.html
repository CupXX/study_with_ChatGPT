代码不是正在运行的软件

Program · Process · Runtime｜目标：看懂“一个项目是怎么从文件变成正在运行的东西”的最小模型。

学完这一课，你应该能解释：
为什么代码明明还在 GitHub / 硬盘里，Worker 却可能已经“不存在了”；以及为什么换 Node 22 / Node 24 会改变程序能不能跑，却不会自动改掉你的项目代码。

01. 先做一个最重要的切分

软件开发里一个非常容易被语言掩盖的事实是：

“有代码” ≠ “代码正在运行”。

你可以把一个项目在 GitHub 放十年。里面的文件不会因为“它是一个程序”就自己执行。它只是静态的软件制品。

当你点击 Run、执行一个命令、启动服务器时，才发生第二件事：某个运行环境开始执行这些指令，操作系统为这次执行建立一个进程（process）。

代码
磁盘上的文件
Runtime
负责让代码能执行
Process
OS 中活着的实例
Behaviour
程序开始做事情

Microsoft 对 process 的最简定义就是：an executing program，也就是“一个正在执行的程序”。进程会得到执行所需的资源，例如自己的虚拟地址空间、系统资源、环境变量和进程 ID。[Microsoft Learn]

02. Runtime 到底是什么？

Runtime（运行时 / 运行环境）是让某类代码真正能够执行的那套软件环境。

以 JavaScript 为例，Node.js 官方直接把 Node 定义为一个 JavaScript runtime environment。Node 使用 V8 JavaScript engine，并在浏览器之外提供文件系统、网络等程序需要的能力。[Node.js]

所以安装 Node 22 和 Node 24，换掉的是什么？

通常不是你的项目文件，而是负责执行这些 JavaScript 文件的 runtime 版本。

同一份代码交给不同 runtime 版本，可能因为支持的 API、依赖兼容性或行为差异而出现不同结果。

这里再加一个容易混淆的点：Runtime 也不是 Process。

Node 是你安装在电脑上的运行环境；当你执行 Node 应用时，操作系统才会创建一个正在运行的 Node process。Node 官方的 process 文档描述的就是“当前 Node.js 进程”。[Node.js Process API]

03. 用你遇到过的 Worker 串起来

A. GitHub / 硬盘里的 Worker 文件
这是静态代码。PowerShell 关不关，它都还在。

B. Node.js
这是执行 JavaScript 的 runtime。

C. PowerShell 里启动后的 Worker
这时操作系统里出现了一个正在运行的 process。它可以持续查询任务、等待事件、处理工作。

D. 结束那个运行中的 Worker
Process 消失了，但代码文件并不会因此消失。下一次仍然可以再次启动，产生一个新的 process。

这也是为什么“代码已经部署/已经存在”和“服务现在活着”是两种完全不同的问题。后面学 deployment、server、worker、container 时，我们都会重新用到这一刀。

04. 再多切一刀：Process 不是 Agent

以后你会学 AI Agent，所以现在先避免另一个混淆：

Process 是操作系统层面的“正在运行的程序实例”。

Worker 是这个程序承担的一种工作角色。

Agent 是一种应用/系统行为模式，它可以运行在某个 process 里面。

它们不是三个平级词。一个 process 可以运行一个 Worker；一个 Worker 里面也可能包含 Agent loop。
